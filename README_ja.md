『ポケモンチャンピオンズ』向けのAgent Skillを4つまとめたパッケージです。AIエージェントから次の作業を行えます。

- 対戦図鑑の確定情報を調べる
- 現在および過去シーズンの環境分布を確認する
- ダメージ、確定数、耐久、素早さラインを計算する
- 根拠を残しながら構築、添削、変更、選出検討、SP調整を進める

4つのskillは同列にインストールされ、それぞれ独立して起動します。`pokemon-champions-team` は構築全体を扱う際に残り3つを連携させますが、単純な図鑑確認、採用率調査、単発計算までteam skillを経由させるわけではありません。

通常の問い合わせは同梱データをローカルで参照します。このプロジェクトが目指すのは構築の強さを単一スコアで表すことではなく、AIが使った事実、計算条件、前提、トレードオフを追跡できる状態にすることです。

## プロジェクトの位置付け

| できること | 想定していないこと |
|---|---|
| Claude Code、Codexなどに導入するローカルskill一式 | アカウント登録が必要なWeb構築サービス |
| 図鑑、環境、計算、実在構築データへの構造化アクセス | モデルの記憶だけで答える百科事典チャット |
| ルール適合性、根拠、信頼度、監査手順を備えた構築支援 | 「客観的な最強構築」を返すブラックボックス最適化 |
| シーズンとレギュレーションが明示された更新可能なスナップショット | 日付を意識せず使える常時リアルタイムDB |

スクリプトが担当するのは事実、計算、決定的な検証です。目的の解釈、候補の設計、取捨選択、最終的な説明はAIモデルが担います。この役割分担がプロジェクト全体の基本方針です。

> [!NOTE]
> **対応データは『ポケモンチャンピオンズ』に限られます。**
>
> 4つのskillが正式に対応するのは、現行の『ポケモンチャンピオンズ』で実装済みのポケモン、フォルム、技、道具、特性、ルールです。過去シーズンの検索もチャンピオンズ内のスナップショットです。『ポケットモンスター ソード・シールド』『スカーレット・バイオレット』など本編シリーズのデータや、未実装情報は対象外です。同名のポケモンや技でも、種族値、威力、特性、習得技、仕様が本編と異なる場合があります。検索と計算ではチャンピオンズ現行値を優先します。

## 4つのSkill

| Skill | 主な用途 |
|---|---|
| [`pokemon-champions-dex`](#pokemon-champions-dex) | 「何者か、何を覚えるか、この名前はどのデータか」 |
| [`pokemon-champions-meta`](#pokemon-champions-meta) | 「今何が多いか、どんな型が使われているか、何が変わったか」 |
| [`ncp-damage-calculator`](#ncp-damage-calculator) | 「どれくらい入るか、確定数はどうか、耐えるか、どちらが先か」 |
| [`pokemon-champions-team`](#pokemon-champions-team) | 「構築を組む、添削する、変更する、選出やSPを詰める」 |

## `pokemon-champions-dex`

パッケージ全体の名称解決も担当する、オフライン対戦図鑑です。ポケモンとフォルム、タイプ、種族値、特性、習得技、技、道具、性格、メガストーンの対応を収録し、一括検索と複数条件の逆引きに対応します。

**得意なこと：**

- 中国語・英語・日本語の名称、一般的な別名、多言語のメガシンカ表記を同一データへ解決する
- 貼り付けた構築、所持ポケモン一覧、技構成をまとめて正規化する
- 「この技を覚えるポケモン」「タイプ・特性・素早さ条件を同時に満たす候補」を逆引きする
- meta、calculator、team間で共通利用するcanonical名を提供する

**注意点：** 図鑑に存在する、または習得可能であるという事実は、環境で一般的であることや採用価値を保証しません。

質問例：

```text
ガブリアスはれいとうパンチを覚えますか？
だいちのちからを覚えるフェアリータイプは誰ですか？
メガリザードンXの種族値と特性を教えてください。
このメガストーンは誰に対応していますか？
```

## `pokemon-champions-meta`

実際の採用状況を調べるための、オフライン優先の環境スナップショットです。season、rule、シングル／ダブルを分離し、ランキングのほか、技、道具、特性、性格、相方、SP分布の詳細パネルを提供します。

**得意なこと：**

- シングルまたはダブルの上位環境を一覧する
- 特定ポケモンの一般的な採用技、道具、特性、性格、相方を確認する
- 技や道具、条件から採用ポケモンを逆引きする
- シングルとダブルの傾向を比較する
- 前回スナップショットとの差分を事実表として確認する

**注意点：** 詳細パネルの技、道具、特性、性格、相方、SPは、多くの場合それぞれ独立した周辺分布です。各欄の1位を組み合わせても、実在する1つの型になるとは限りません。また、採用率は強さの証明ではありません。

質問例：

```text
現在のM-Bダブルで採用率上位20体を教えてください。
メガメタグロスの採用技はシングルとダブルでどう違いますか？
今回の更新で順位や道具採用率が大きく変わったポケモンは？
ダブルの追い風要員は誰と組まれることが多いですか？
```

配布リポジトリ直下には、`<season>_<date>_{zh,ja,en}.xlsx` という3種類の単言語ワークブックも含まれます。シングル／ダブルの全表と事実ベースの更新レポートを、スクリプトを実行せずに閲覧できます。

## `ncp-damage-calculator`

同梱のNCP VGC Damage Calculator coreを使用する、『ポケモンチャンピオンズ』用ダメージ・素早さ計算skillです。攻撃側と防御側のSP、性格、道具、特性、ランク補正、技、場の状態を指定し、全乱数、割合、確定数、耐久結果、行動順を返します。

**得意なこと：**

- 特定攻撃のダメージ範囲と確定1発／2発ラインを計算する
- 指定した型が攻撃を耐えるか確認する
- 2体の完全な素早さ状態を比較する
- 追い風、トリックルーム、こだわりスカーフ、天候込みの素早さラインを調べる
- team skillの対面評価とSP調整に厳密な計算結果を提供する

**注意点：** 計算に成功しても、その型がチャンピオンズで合法とは限りません。また、完全なターンシミュレーターではないため、回復の反復、状態変化、PP、非公開情報、双方の選択分岐までは扱いません。未指定の型や場の条件は前提として明示する必要があります。

質問例：

```text
いじっぱり攻撃SP32のメガメタグロスが使うじしんは、このメガライチュウYにどれくらい入りますか？
このガオガエンは一般的なガブリアスのじしんを確定で耐えますか？
追い風下ではどちらが先ですか？トリックルームだと順番は変わりますか？
目標を抜くには素早さSPがあといくつ必要ですか？
```

## `pokemon-champions-team`

構築全体を扱う専用skillです。新規構築、未完成構築の補完、ルール適合性の確認、構造診断、環境への対面確認、選出検討、メンバー変更、SP調整を担当します。残り3つのskillと同列に配布されますが、構築タスクの内部では図鑑情報、環境データ、厳密計算を1つの監査可能な流れへまとめます。

単に一言からそれらしい6体を返すジェネレーターではありません。ユーザーの意図、現行環境、実在する同時採用データ、再計算可能な対面情報をもとに、単一の合成スコアに頼らず、説明可能な提案を作るためのskillです。

> [!IMPORTANT]
> **AIによる構築回答の最低品質を底上げしますが、上級者の構築経験そのものを代替するものではありません。**
>
> 古い記憶、名称の取り違え、違法な型、計算ミス、独立した採用率から作った架空の型、ユーザー条件の見落としといった失敗を減らし、事実面と推論手順の下限を上げます。一方、候補の質や説明の深さは、skillを動かすモデルによって変わります。実際の操作感、選出傾向、想定相手、試合中のプランに構築が合うかどうかは、ユーザーから与えられる対戦情報にも左右されます。

最初の出力を自動生成された最適解とは考えないでください。より良い結果を得るには、狙っている勝ち筋、基本選出や初手、よく当たる相手、許容できる弱点、実戦で負けた場面、すでに持っている人間側の知見を伝えることが重要です。まず根拠付きの案を作り、実戦やリプレイで問題を確認し、その内容を返して再調整する使い方が最も効果的です。

### 入力方法

決まったファイル名や、ユーザーが覚えるべきスキーマはありません。次のような入力を利用できます。

- 「このポケモンを軸に組んで」という自然言語の依頼
- Showdown形式の構築テキスト
- 既存のteam JSON
- 各メンバー、技、SPを文章で記したメモ
- 構築や所持一覧を保存した任意のローカルファイル
- agentが先に読み取れる鮮明なスクリーンショット
- 「所持ポケモンのみ」「このメガ枠は固定」「トリックルーム禁止」といった条件

agentはポケモン、技、道具、特性、性格をdexで解決し、構築情報、ハード制約、ソフトな希望、対面目標を検証可能な構造化入力へ整えます。ユーザー側で形式を加工する必要はありません。

### 機能一覧

| 機能 | team skillが行うこと |
|---|---|
| **入力とルール適合性** | 文章、Showdown、JSONを読み、名称とフォルムを正規化します。使用可能ポケモン、習得技、特性、道具、同種・同一道具制限、登録数、SP、メガシンカ関係を確認し、`valid` / `invalid` / `unknown` を区別します。 |
| **構築診断** | 防御タイプ、攻撃範囲、素早さ構造、S操作、役割に関する客観的な兆候を個別に示し、総合点へまとめません。 |
| **対面と選出** | 現行meta上位に対する双方のダメージ、素早さ、確定数を計算し、シングル6→3、ダブル6→4、1試合1回のメガシンカなど選出時の制約を確認します。「最善選出」を自動決定しません。 |
| **SP調整** | 「Xを耐える」「Yを抜く」「Zを確定1発／2発にする」を明示的な対面目標へ変換し、必要最小SPとその代償を調べます。唯一の最適配分を探索する機能ではありません。 |
| **候補と実在構築データ** | 不足要素から補完・交代候補を探し、変更前後の事実を比較します。実在する同時採用構造、代表的な型、完全な実在構築サンプルを、AIが独自案を組むための根拠として使います。 |
| **結果の検証** | すべての候補に同じ事実チェックを適用し、違法またはハード制約違反の案を除外します。最終回答の前提、トレードオフ、調整説明、再現できない数値の有無も確認します。 |

### 構築タスクの進み方

内部では「先に感覚で生成し、後から理由を付ける」進め方を避けるため、手順化された検証を行います。ユーザーが各内部コマンドを覚える必要はありません。全体は次の4段階です。

1. **目的を整理する：** ルール、軸、使用可能範囲、固定条件、プレイ方針、必要な対面ラインを確認します。自由度の高い新規構築では少数の質問を分けて行い、既存構築の添削では本当に不足している情報だけを聞きます。
2. **データで裏付ける：** 現行環境と実在構築の両方を確認し、「何が多いか」と「何が実際に同時採用されているか」を分けます。独立した採用率欄から架空の型を作りません。
3. **候補を比較する：** 1つ以上の方向性を作り、同じルール適合性・構造・対面・信頼度チェックを適用します。各変更で何を改善し、何を失うかを示します。
4. **検証して提示する：** 必要なダメージ、素早さ、選出、SPラインを計算し、最終文章の数値、前提、トレードオフを再確認してから、ユーザーが判断・反復できる形で提示します。

この流れが保証するのは、根拠を追えること、条件を落としにくいこと、数値を再計算できることです。特定の対戦思想が常に正しいと判定したり、客観的な最適構築として認定したりはしません。

### 主な使い方

| 依頼 | 処理内容 |
|---|---|
| **ゼロから構築する** | 「チーム構築フローを開始して」と言えば完全なガイドへ入ります。通常の構築依頼では不足情報のみを順番に確認し、比較・検証済みの方向性を提示します。 |
| **既存構築を添削・変更する** | 現在の構築を整理し、まずルール適合性と構造を確認します。必要に応じて環境対面を追加し、交代案ごとの改善点と代償を説明します。ユーザーが固定した軸を勝手に外しません。 |
| **選出、対面、SPを詰める** | 内容に応じて6→3/4の選出、環境全体への対面表、具体的な閾値調整を使い分けます。「今の型で耐えるか」と「耐える型へ変更してほしい」を同じ計算として扱いません。 |

### 実在構築データの扱い

配布版には、シーズン、レギュレーション、シングル／ダブルごとに分けた実在構築サンプルが含まれます。価値があるのは**同時採用の事実**です。6体の並び、1体の道具・特性・技・性格・SPが同一の観測セットに由来するか、特定の証拠区分でどの構造が繰り返し現れるかを確認できます。

このライブラリはランキングではありません。

- 戦績、順位、レート、サンプル数を強度スコアへ変換しません
- シングルとダブルを混ぜず、旧レギュレーションを現行証拠へ自動混入させません
- 6体のみ判明しているデータは同時採用の参考にはなりますが、完全な代表型として扱いません
- 標準型キャッシュは常に低信頼度の参考であり、ユーザー構築は実際の型で再計算します
- AIは実在する完成構築を資料として読めますが、無断で「推奨構築」として丸写ししません。そのまま採用する場合は、サンプルとの一致、採用理由、検討した変更案を開示します

### 出力の読み方

**ルール適合性は単純な二択ではありません。** `valid` は利用可能な事実に基づく決定的チェックを通過した状態、`invalid` は修正可能なエラーあり、`unknown` は入力または根拠不足です。不明を適合済みとして扱いません。

**採用率は強さではありません。** ランキング、実在構築での同時採用、戦績タグは別々の観測です。AIはトレードオフを説明したうえで提案できますが、skillが不透明な総合点へ合成することはありません。

**CHECKラベルは対戦シミュレーターではありません。** C2/C1/C0は、評価対象の型、ダメージ、素早さ、ターン予算に基づく受け出し、対面・死に出し、明確な処理手段なしという関係を表します。積み技、回復、状態異常、PP、長期戦は明示された範囲でのみ注意点として扱われます。

**信頼度も結論の一部です。** 実在する同時採用セット、周辺分布からの補完、標準型キャッシュ、薄いサンプル、一部計算失敗では、信頼度（confidence）と注意事項（caveat）が異なります。重要な前提は最終回答にも残す必要があります。

### 質問例

```text
M-Bダブルのチーム構築フローを開始して、必要なことを順番に聞いてください。

メガムクホークを軸にシングルを1案だけ作り、重要なトレードオフを説明してください。

このShowdown構築のルール適合性、構造上の穴、現環境上位20体への対面を確認し、変更案を出してください。

roster.txtにいるポケモンだけでダブルを組んでください。ゲンガーは固定、トリックルームは使いません。

この6体から4体をどう選出しますか？相手によってどの選出軸を変えるべきですか？

指定したガブリアスのじしんをガオガエンが確定で耐えるよう調整し、どのSPを削るか示してください。

AをBへ変更した場合の防御、S操作、環境上の穴を比較してください。採用率だけで判断しないでください。

この2体を含む実在構築の共通構造とバリエーションを調べ、完成構築はそのままコピーしないでください。
```

## 4つのSkillの連携

1つの依頼で複数skillを使う場合も、事実の担当範囲は明確に分かれます。

```text
ユーザーの自由入力
  ├─ 名称・フォルム・習得技・道具の適合性 ──> dex
  ├─ 現行採用率・各項目の周辺分布 ─────────> meta
  ├─ 条件指定したダメージ・素早さ ─────────> calculator
  └─ 構築意図・候補・診断・調整 ───────────> team
                                             └─ 必要に応じて上の3つを利用
```

たとえば「メガメタグロス軸のM-Bダブルを組み、このガブリアスのじしんを耐えるようにしたい」という依頼では、名称とルール適合性、現行採用率、実在構築の構造、候補比較、耐久ライン計算を組み合わせます。「メガメタグロスのタイプは？」ならdexだけで完結し、構築フローには入りません。

## インストール

4つのskillはまとめてインストールされます。導入後のコマンド登録は不要で、agentが各`SKILL.md`の説明から適切なskillを選びます。

### 方法A：1コマンド

先に[Node.js](https://nodejs.org/)を導入し、プロジェクトディレクトリで実行します。

```bash
npx skills add pmwl0128/pokemon_champion_agent
```

全プロジェクトから使えるグローバル導入：

```bash
npx skills add pmwl0128/pokemon_champion_agent -g
```

## 初心者向け：自分の対戦プロジェクトを作る

skillはグローバルにも導入できますが、継続して構築を調整するなら専用プロジェクトを用意する方が便利です。所持一覧、構築、対戦メモ、agent向け指示を同じ場所へ置くことで、次回以降も有用な文脈を引き継げます。

### 1. プロジェクトを作成

```bash
mkdir my-champions
cd my-champions
```

ディレクトリ名は自由です。IDE型agentではこのフォルダを開き、CLI型では移動してからClaude CodeまたはCodexを起動します。

### 2. 4つのskillを導入

上記の[インストール方法](#インストール)から1つを選びます。プロジェクト単位で導入する場合は、作成したディレクトリ内で実行します。

```bash
npx skills add pmwl0128/pokemon_champion_agent
```

Windowsでリンク作成に失敗した場合は、「agentにインストールを依頼」または「手動コピー」を使い、4つすべてをプロジェクトの`.claude/skills/`か`.agents/skills/`へ配置します。

### 3. プロジェクト指示を追加（任意・推奨）

配布版のルートには`CLAUDE.md`と`AGENTS.md`が含まれます。用途に応じて片方または両方を自分のプロジェクト直下へコピーします。

- Claude Codeでは`CLAUDE.md`
- Codex、または`AGENTS.md`を認識するagentでは`AGENTS.md`
- 複数のagentで同じプロジェクトを開く場合は両方

これらのファイルには、4つのskillの使い分け、現行環境の確認、記憶ではなくskillで対戦事実を調べること、構築タスクでteamの手順を守ることが記載されています。なくても動作しますが、長い指示の維持が苦手なモデルでは特に有効です。

### 4. 自分のデータを追加（任意）

ファイル名や形式は自由です。

```text
my-champions/
  CLAUDE.md           # 任意
  AGENTS.md           # 任意
  roster.md           # 所持ポケモン
  current-team.txt    # Showdown形式または文章の型メモ
  matchup-notes.md    # 対戦記録、頻出相手、変更案
```

固定スキーマはありません。「`roster.md`のポケモンだけを使う」「`matchup-notes.md`を踏まえて再検討する」のように、agentへパスと用途を伝えてください。agentが内容を読み取り、正規化してから対応skillへ渡します。

### 5. 質問し、結果を蓄積する

プロジェクト内でagentを起動し、たとえば次のように始めます。

```text
ガブリアスはりゅうのまいを覚えますか？
current-team.txtのルール適合性と環境対面を確認してください。
roster.mdにいるポケモンだけでシングル構築を作ってください。
matchup-notes.mdの負け筋を踏まえて変更し、固定した軸は残してください。
```

構築の各版と対戦メモを残しておくと、毎回空の会話から作り直すよりも、自分のプレイに合った調整を続けやすくなります。

## モデルによるSkill起動と手順実行の差

skillの自動起動は、agentが`SKILL.md`を正しく読み取り、タスク中も指示を維持できることに依存します。すべてのモデルで同じように強制される実行機構ではありません。ツール利用や長い指示の追従が弱いモデルでは、記憶だけで回答する、事実skillを1つしか呼ばない、teamの内蔵手順を一部省略するといったことがあります。

その場合は、依頼内で明示してください。

```text
最初にpokemon-champions-team/SKILL.mdを読み、team skillの完全な手順でこの構築依頼を処理してください。
記憶だけで答えず、名称とルール適合性はdex、採用率はmeta、ダメージと素早さはcalculatorを使ってください。
候補比較、ルール適合性の確認、最終検証を省略せず、team skillの内蔵フローに従ってください。
```

同梱の`CLAUDE.md`または`AGENTS.md`をプロジェクト指示として使うと、skillの振り分けと手順実行が安定しやすくなります。ただし、これらのファイルがモデルへ高度な対戦知識を与えるわけではありません。ツール結果を繰り返し無視する場合は、補助プロンプトを増やすより、ツール利用と長い指示の遵守に強いモデルを使う方が効果的です。

## 利用時のポイント

1. 任意のプロジェクトディレクトリで、Claude Code、Codex、またはAgent Skills互換のagentを起動します。
2. 中国語、英語、日本語の自然文で質問できます。CLIコマンドを覚える必要はありません。
3. 構築、所持一覧、条件は会話へ貼り付けても、任意のローカルファイルに保存してパスを伝えても構いません。決まったファイル名はありません。
4. 現行環境に関する回答では、ページ上部のseason/rule/as-ofを確認してください。新しいデータが必要ならskill一式を更新します。
5. agentが想定どおりskillを使わない場合は、対応する`SKILL.md`を先に読むよう指示します。同梱の`AGENTS.md`と`CLAUDE.md`もプロジェクト指示として利用できます。

## 環境ワークブック

正式リリースごとに、シングル／ダブルの全スナップショットと更新レポートから3つのワークブックを再生成します。

```text
<season>_<date>_zh.xlsx
<season>_<date>_ja.xlsx
<season>_<date>_en.xlsx
```

各ファイルの主言語は1つです。中国語版と日本語版には照合用のcanonical英名列も含まれます。主なシートは次のとおりです。

| シート | 内容 |
|---|---|
| シングル／ダブル | 順位、名称、採用技、道具、特性、性格、相方、SP分布 |
| 更新レポート | 前回からの順位変動、新規・圏外、構成変化の事実表と名称連動検索 |

ワークブックはfacts-onlyのレポートであり、AIによる環境解釈は含みません。

## データ鮮度と機能上の限界

- metaと実在構築データは環境とともに変化します。配布版が保証するのはページ上部に記載したローカルスナップショットであり、リアルタイム性は主張しません。
- dex、meta、teamサンプル、calculatorは同梱データを参照するため、通常利用にネットワークは不要です。新しいデータはskill一式の更新で取得します。
- 過去seasonも検索できますが、旧レギュレーションを現行証拠へ自動混入させません。
- 図鑑データや計算式もルール変更の影響を受ける可能性があります。レギュレーションをまたぐ質問では対象season/ruleを明示してください。
- 全ターン状態、非公開情報、双方の選択を網羅することはできません。前提（assumption）、信頼度（confidence）、注意事項（caveat）も結論の一部です。
